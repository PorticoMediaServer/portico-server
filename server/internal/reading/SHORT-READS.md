# Short reads, extraction rule 1

Root9 fixes membership to complete current canonical-primary publication text with `0 < wordCount < 45000`, at 250 words per minute. SQL applies this predicate and ordinary viewer/library/profile visibility before the row limit. The title's deterministic availability-first primary is shared with List; a shorter alternate never substitutes. Results use added time descending and entity ID descending as stable ties. The public estimate rounds `wordCount * 60 / 250` up to whole seconds for duration presentation, never for eligibility. No private learned pace is read.

The initial extractor supports admitted EPUB XHTML spine documents. It counts every spine occurrence in reading order and requires complete XML through EOF, a single XHTML html root/body, and only the XHTML namespace. It counts body character data, excluding script, style and template subtrees. Inline elements preserve text runs; the explicitly enumerated block and line elements separate them. A word is a maximal Unicode letter/number/combining-mark run containing a letter or number; punctuation separates runs. Han, Hiragana, Katakana, Thai, Lao, Khmer and Myanmar text withholds the entire count until a dictionary/word-segmentation extractor is available. This is a narrow deterministic Portico rule, not a claim of universal linguistic word segmentation.

A document over 8 MiB, total spine text over 64 MiB, XML nesting over 256, a directive/entity the safe XML decoder cannot handle, foreign embedded markup, malformed XML, unavailable member, cancellation or interrupted acquisition never produces a partial final count. Unknown is NULL; an actual complete zero count is zero, and neither qualifies. PDF has no admitted server text-layer extractor yet, so it remains unknown. Image-only CBZ is not counted. Unknown/unextractable publications remain readable and browsable.

Counting happens once on the existing principal-authorized acquired source during Prepare, outside the writer lock. It performs no provider search, second version acquisition, background credential retention or progress write. The cache is exact inventory row + inventory revision + rule version; accepted replacement or rule change cannot reuse the old count. The adoption transaction repeats the original principal selection and compares original source/physical revision and inventory row before writing. The source is physically revalidated after extraction. Only count metadata is retained, never extracted book text.

Discover opts into this real producer with shortReadsLimit for an explicit library. Until an item has an accepted complete count it is omitted; this initial custody does not claim that every never-opened library title has been scanned. A future authorized inventory extractor can populate the same evidence under the same complete/current rule. No client guesses membership from loaded cards.

Official API and persistence metadata generation remains Release16 checkpoint-owned.
