# Remaining scope and extension boundaries

Revision: portico.reconciled.1. The CAP-001–CAP-066 inventory remains committed subject only to explicit user deferrals: remote audiobook enrichment, later platform rollouts and future separate paid relay. Historical I0/I1/I2/S1 labels are sequencing proposals, not authority to delete features or silently reduce initial scope. Unsupported individual devices/operations may be capability-gated honestly while their required implementation remains in the ledger.

## Music, chapters, subtitles, lyrics and optimization

Full music/audiobook product behavior remains: typed artists/releases/discs/tracks, authors/books/series/chapters, queues, listening state, playback speed, sleep timer, repeat/shuffle, lyrics and supported output controls. Gapless, crossfade and normalization are separate opt-in features, each requiring real boundary evidence and device support; one feature does not imply another. Instant mix is server-defined authorized membership/ranking with reproducible continuation, not a client shuffle of a fixed first page. Remote audiobook metadata is the only audiobook deferral; local tags/sidecars, chapter-accurate playback/resume and library presentation stay required.

Subtitle/lyric upload, offset, replacement and deletion are exact resource/version/revision operations. Validate format, size, encoding, timestamps and path/origin containment; retain provenance, language, rights and owner/user scope. An offset edits timing intent for that track, not the source media clock. New content is staged/validated and becomes a new immutable asset revision. Active plans keep their pinned track until an explicit supported replacement transition; a late old upload cannot supersede a newer choice. No arbitrary HTML/script renderer or provider-secret URL is sent to clients. Search/apply fetches through the server's permitted provider adapter. A viewer permission does not grant filesystem write access beside media.

Chapters/skip markers/trickplay bind the exact source revision and timeline from document 32. Deep analysis uses Complete/Custom permissions, bounded background jobs and versioned results; speculative intro/credit detection is not an automatic trusted skip. Owner edits are CAS and preserve provenance. Unsupported markers are hidden, not false promises. Prepared optimization derivatives have stable transformation/source/digest identity, explicit owner intent, durable cancel/retry and lease-aware pruning. They never replace the original media or become source identity by convenience.

## API and third-party clients

The public API is a supported client boundary: documented authentication, exact scope, capabilities, paging, media planning/delivery, renewal, errors and cancellation semantics. It must be usable without reproducing first-party React state or a private endpoint handshake. Public schema/version and semantic conformance fixtures ship with the owning implementation, separate from these private planning documents. Unknown required semantics fail with a compatibility outcome; optional safe read additions need not break existing clients. Third-party clients still satisfy permission, source and grant boundaries. Broad API keys cannot impersonate interactive owner reauthentication.

Retain DLNA discovery/content-directory/renderer capability as a scoped compatibility adapter. No anonymous full-library browse or unscoped media endpoint is authorized merely because the requester is on LAN. A qualified content-directory client must supply an authenticated, least-privilege server scope; an owner explicitly configures permitted visibility. A renderer controlled by an authorized sender may receive only the exact playback's expiring capability and permitted child resources, never an account token. Document 32 governs any URL capability and expiry/redaction; source paths and private metadata remain protected.

Unsupported authentication/grant/header/child-resource behavior is an explicit per-renderer capability limitation. Do not loosen the server API for generic legacy devices or implement credential-free public browsing as a shortcut. Before advertising each DLNA mode, demonstrate authenticated directory isolation, renderer start/seek/stop/renewal, loss/revocation and off-origin child-resource denial. This retains the feature obligation while refusing to claim universal legacy compatibility.

## Feedback and notifications

Viewer feedback is a selected-server feature with a stable report ID, exact actor/media/context scope where authorized, safe bounded user text and optional explicitly selected diagnostic attachments. The submitter may see their own report/status; owner triage is separately authorized. Idempotency prevents duplicate reports after lost response. Sanitize/escape user content, bound upload size/type and redact before attachment persistence. Do not forward reports, screenshots or media context to Hosted automatically.

Owner triage has explicit status/revision/history and reply/resolve semantics. Notifications are profile-owned server inbox records with stable IDs, read state, pagination and retention. A revoked/inaccessible target may remain a generic status notice but cannot disclose its old private metadata. Notification creation/delivery/read state is not proof that the underlying operation succeeded. Account/security notices use the identity authority; ordinary media/room/owner diagnostics remain local. Only the contracted optional opaque invitation/account wake can involve Hosted, with bounded expiry and no media payload.

## Distribution, website and operator features

Server installers/services and containers must isolate binaries, state, generated storage, keys and media; include clean install, restart, upgrade, rollback prerequisites and uninstall evidence per OS. Default port 32500 is a product default, not a reason to seize a used development port. Release artifacts need exact provenance, hashes/signatures and truthful platform/runtime requirements. Future versions are OS services; a foreground development command is not installer completion.

Public website/features/docs/downloads/legal/support/abuse/developer routes remain required product scope. Every offered download must exist and match its displayed version/platform; unsupported platforms are described honestly. Public API documentation is distributable product documentation when expressly included in release scope; these internal plans, audit snapshots and private fixtures remain excluded. This review neither publishes a site nor revises legal documents/provider agreements.

Hosted operations use separate operator identity, least privilege, explicit secret management, health/readiness, bounded logs/metrics, certificate/DNS job recovery, database backups and restore drills. No operator console gains access to a user's local library or catalog. One self-managed PostgreSQL VPS is the initial architecture; scale targets require actual benchmarks and measured headroom, with additional VPSs/HA introduced when evidence warrants. No per-user/media telemetry platform or managed-database dependency is added.

## Platform expansion and entitlements

React Native is mandatory wherever viable; native media/input/auth/storage adapters are expected. Android phone/TV, Fire TV and Vega retain their own install/auth/browse/play/state/input/accessibility qualification. Roku, Tizen and webOS are outside this programme; CarPlay, Android Auto and light theme are excluded. Runtime/package compatibility is verified for each target rather than inferred from its brand. A simulator or shared package cannot certify HDMI/HDR/audio routing, background transfer or physical remote behavior. Current testing remains confined to authorized existing simulators.

Relay remains a future paid feature operated separately. Hosted may reserve account entitlement identity/flags, but all other Portico capabilities remain free. A reserved flag is not authorization to deploy relay transport, meter ordinary direct playback, add billing flows or paywall owner diagnostics. The server/frontend may describe relay as coming soon only in the agreed location and with honest unavailability. Future relay design must independently specify cost, privacy, entitlement enforcement, transport and outage behavior before implementation.

## October release boundary

All applicable first-party features remain release requirements; implementation reports, not this scope ledger, establish completion. Film/TV/anime/music/audiobooks, Live TV/DVR/downloads/state/discovery are included. Fix casting/Watch Together defects without redesign. No email, consumer push, plugins/themes/custom CSS or watch-state import/export. Server platforms are Windows/macOS/Linux/Docker; own-hostname proxies/overlays/IPv4/IPv6 are supported, sub-paths excluded.
