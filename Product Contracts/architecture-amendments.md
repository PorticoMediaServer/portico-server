# Domain architecture and failure boundaries

Revision: portico.reconciled.1. These sections complete the reconciled family contracts. They specify cross-component mechanics without importing legacy code or defining a second playback protocol. Each named clarification supersedes the corresponding legacy implementation assumption; original product choices otherwise remain intact.

## Identity, onboarding and account lifecycle

Eight active profiles includes the primary profile. Enforce creation under an account lock in both Hosted and Local authority. Server profile-directory projections, native/web create controls and tests share the same product limit. Defensive decoding limits may be larger to report inconsistent development state; never silently truncate a directory, delete extra records or invalidate a whole account merely to repair the cap. Existing over-cap development data requires an explicit repair, not automatic deletion. PIN/order/art/deletion remain required features, not implied by create/rename completion.

Account-only security operations do not require a selected media server or viewing profile. Profile management belongs to the account/primary profile as contracted; server ownership does not grant control over another account's Hosted profiles. The completed account creation flow still requires verified contact email and supported Google/Apple onboarding. Current password-only/no-email integration is incomplete, not permission to change that UX.

Account/session mutations lock in a consistent account-before-family order, validate expiry after lock acquisition, and fence credential rotation/revocation atomically. A rename changes display metadata, not authentication-family identity. Client callbacks bind the originating account/family and cannot sign out a newly selected account after a late response. Current account-session review's family-scoped design is retained.

Claim ownership has one stable server identity, one pending claim lineage and durable install acknowledgment. Setup secret, human code, device poll proof, claim receipt, account family and server family are different credentials. Issuing one never supplies authority for another. Commit and lost-response recovery must bind exactly the same credential family; recovery receipt expires if that family was revoked. Never recover credentials merely because an old approval exists. Cancellation accepted before claim commit fences it; after commit, abandonment requires result reconciliation, not a fictional rollback.

Hosted account/profile deletion has one tombstone revision and idempotent per-server erasure outbox. A server processes the latest tombstone before granting fresh access. Reachable/acknowledged/pending-offline servers remain distinguishable; retrying a tombstone never recreates a deleted profile. Recordings and shared resources follow explicit ownership/retention resolution, not cascading file deletion. Restore cannot resurrect erased authority.

Device-code alphabet/length and ten-minute lifetime are retained. A local authority can reserve its own codes, not ensure uniqueness across every disconnected server. Manual approval always establishes the intended Hosted or exact Local server context first. Do not introduce a global local-code registry or a Hosted dependency into Direct Sign-In.

## Connectivity and fleet recovery

Route location, server identity, credential validity and membership validity are four separate facts. Public route validation requires valid HTTPS plus proof that the endpoint controls the pinned server identity; a static `/system` fingerprint string is insufficient. For endpoints that need explicit identity proof, use an unpredictable client nonce, short validity, a server-identity signature over nonce/server/protocol/endpoint context, and strict replay/context validation. This proof supplements the authenticated transport; it does not make plaintext confidential or prevent a relay by itself.

Native transports may enforce a pinned TLS identity where supported. Browser transports use ordinary trusted HTTPS and application identity validation; they cannot pretend to support arbitrary custom certificate trust. The existing explicit local HTTP policy remains a trusted-LAN exception. Do not advertise HTTPS-grade confidentiality for it or use it for public remote access. Initial Direct Sign-In pairing is explicit trust establishment, never automatic trust in Bonjour labels. Keep account passwords/Hosted credentials off unrelated server origins.

Changing LAN/public routes must preserve stable server/viewer/playback identity. A signed route document's expiry ends its authority; remembered verified addresses may still be probed as hints without querying Hosted on every screen. Fresh identity proof plus valid server-native authority is required. A topology generation invalidates old probe results and certificate/DNS jobs; a slow old probe cannot publish a current route. Cached DNS, IPv4/IPv6 changes and certificate replacement must not erase credentials or silently trust a different server key.

Seven-day policy, unchanged daily renewal, nominal thirty-minute heartbeat, forty-five-minute presence and the 500ms discovery hedge remain as contracted. Presence is directory freshness, not media authorization. A reachable server can serve valid direct sessions despite stale Hosted presence. Signed policy renewal with identical content may extend expiry without generating a new semantic revision; same-revision different content is rejected. A thirty-day offline profile proof does not extend seven-day online Hosted-member authority. A valid downloaded-artifact receipt is independently usable offline until its own thirty-day deadline unless revocation is learned.

Persist last acknowledged policy/profile/network generations and coalesced wakes in PostgreSQL. Wake success means outbound notification delivery; convergence requires the exact server acknowledgment. Retry backoff, retry-after and jitter survive worker restart. On cold restart, paginate overdue servers by indexed next-due time and bounded worker leases; do not probe the entire fleet synchronously, rewrite all leases, or drop pending invalidations. Return bounded retry guidance during overload. Steady-state request cost is measured separately from authentication, revocation bursts, reconnection and daily renewal.

DNS remains a public stateless address-encoding service with no Hosted DB/secrets. Hosted remains behind Cloudflare; client-to-server media remains direct. Private key generation stays local. ACME challenges and retries are durable per-server namespace/identity operations; uncertain issuance is reconciled, not repeated blindly. Do not conflate the origin certificate for Cloudflare-hosted services with direct-server certificates.

Fixed-wireless/CGNAT inability to accept unsolicited inbound traffic is a truthful remote-access limitation, not an authentication failure. LAN, valid IPv6, configured reachable public/manual routes or an explicitly deployed supported network path may work. This pass does not invent free relay, require port forwarding where impossible, or promise NAT traversal that has not been implemented and tested. Relay remains the separate future paid feature.

## Sources, inventory and catalog identity

One library has multiple independently configured sources. Source ID and configuration generation own the root, credentials and inventory; object ID owns observed storage identity; source revision owns exact byte evidence; logical media/version IDs own user-visible catalog identity. A shared physical asset can back several logical links. Neither library root nor asset path is the identity. A rename requires strong continuity evidence before preserving identity; replacement at the same path must invalidate old technical facts and cannot silently retarget an old plan to different bytes.

Inventory publishes provisional visible items before technical analysis. A probe failure leaves an inventoried item with incomplete facts; it does not fail or hide every later item. File List Only is enforced at the final read boundary and performs no media/sidecar/STRM content reads. On-demand playback probing remains a separate authorized foreground operation. Metadata matching, Basic and Complete stages have their own durable outcome and exact revision fences.

A complete inventory generation records source config/root identity, coverage frontier, observed object identities, errors and terminal commit. A healthy root check alone is not proof that its contents were fully enumerated or that an absent network mount has not exposed the empty directory beneath it. Root/mount identity change, partial subdirectory failure, lost cursor or access loss disables absence reconciliation for affected coverage. Rechecking the same path successfully is insufficient.

Provider snapshot/delta tokens are used when available. Without stable remote pagination, a completed traversal is observation evidence, not automatically a point-in-time snapshot: retain seen IDs in bounded disk-backed pages, detect inconsistent pagination, and require corroborated healthy observation/grace before missing-state publication. Never hold a network snapshot through a DB write transaction. Missing grace is an explicit source policy; absence alone never deletes physical media.

Object availability is source-owned; a library link can be unavailable independently. A scan of one library must not globally mark a shared asset unavailable merely because that library no longer links to it. Removing a source detaches its links and waits for active leases before physical/private cleanup. Removing a catalog link differs from owner-confirmed physical file deletion. Physical deletion requires current path/root identity, all-reference review and no active artifact/source lease; reject unknown ownership rather than guessing.

Use the same source-revision identity interface that playback's new media-source work owns. Do not implement a competing ETag/path interpretation for the scanner. Local size/mtime alone is weaker evidence than available object/file identity and cannot certify all replacements. Exact continuity requirements and uncertainty are carried explicitly into playback plans.

Managed rclone inventory uses provider listings; its optional compatibility mount is not scanner truth. User-managed OS mounts remain local/network filesystem sources. A configured mount path is not evidence of an active mount; compare the actual owned process/mount generation. Never stop another process by name or adopt another user's mount. Owner-supplied executable replacement requires revalidation; no automatic binary download. Native WebDAV and STRM use bounded authenticated remote adapters and per-connection SSRF policy, not URLs leaked into client or FFmpeg command arguments.

## Metadata and artwork publication

Preserve TMDB primary/TVDB fallback or selectable policy, AniList anime default from the original contract, MusicBrainz's typed identity, local evidence preference and local-only audiobook enrichment. Disabled providers make no calls. Initial provider-query disclosure and confirmation remain required; preconfigured project credentials do not imply owner consent to send queries. Project identifiers are distributed application inputs, not user secrets, and no Hosted broker is introduced.

Separate immutable candidate evidence, accepted identity, manual decisions, effective display projection and technical facts. Display title must not become a replacement matching key after an owner edit. Provider searches use source/accepted identity evidence. Each result carries item identity, source evidence revision, provider policy/locale, accepted identity revision and metadata base revision. Revalidate them immediately before publication; any mismatch discards/requeues the stale result. Do not let a trigger that protects two scalar fields stand in for whole-domain revision/provenance enforcement.

Manual changed fields remain locked by default. An explicit clear-to-empty differs from removing an override; Unlock alone preserves the current value until an authorized refresh. Undo creates a new revision, retaining intervening evidence. The current small editor's `null` to restore an automatic value is an explicit reset action, not a general implementation of Unlock. Keep that limited action labelled truthfully.

Matching thresholds 0.85 and 0.12 margin are minimum acceptance rules, not a statistical calibration claim. Persist reasons for independent signals and hard contradictions; do not count the same filename parsed twice as two signals. A conservative exact title/year match may remain, but provider popularity alone cannot authorize identity. Name equality never merges people or media editions. Typed provider crosswalks and owner Identify are explicit identity changes.

Hierarchy reconciliation pages descendants and records old/new ordering/parent evidence. Pin active playback to its accepted source/timeline; metadata renumbering does not reinterpret a playing episode or audiobook chapter. Large merges stage a closed reference map, preserve provenance and personal-state conflicts, and atomically publish the canonical alias/projection generation. Resolve aliases without cycles/unbounded chains. Unknown referencing modules block merge publication. New modules register references before exposing records; background rewrites may later compact already-resolvable aliases. Undo is permitted only where resulting references/state can be reconciled safely; an old snapshot cannot overwrite newer user intent.

Selected artwork is an immutable, verified, locally retained asset referenced by a metadata revision. Acquisition is a background/explicit metadata operation, never a provider call made by an interactive image response. A cache miss returns an authorized deterministic fallback and queues deduplicated repair; it must not serialize every image request behind one provider download lock. Stage downloads with size/type/dimension bounds, install then compare revisions before selecting. Retention must not evict a still-selected original; generated derivatives are disposable and locally regenerable. Provider failure retains the previous valid selection. Rights-specific purge is a separate policy operation and never deletes independent manual/local data or media.

## Personal state, Saved resources and offline artifacts

Stable viewer ownership follows Foundation. Account-wide limits and per-profile data are separate. APIs may encode the original integer 0–10 personal rating as five half-star steps with null for unset, provided adapters document the lossless mapping (`stars = rating/2`, zero ↔ null) and clients preserve the same choices. This is representation reconciliation, not an instruction to redesign the existing rating UI.

Catalog/provider collections and user-created collections are separate resources. A library-level collection table is not a substitute for profile ownership/shares. Playlist entries and queue entries have stable occurrence IDs; duplicates stay meaningful. Server-side reorder/query membership uses CAS. A full-order request may be bounded, but large playlists need a server-side move-before/after or staged reorder operation rather than a hidden permanent first-N content limit. The server calculates membership and ordering; clients never download the entire library to sort it.

Personal mutations name exact fields and expected revisions. Concurrent unrelated fields may reconcile independently; contradictory explicit edits from a common base create an unresolved conflict, preserving the last uncontested value. Store the required base value/revision and per-device operation sequence, not client timestamps as authority. If the base is outside retained history, return needs-review; never invent an ancestor. Online playback arbitration is exclusively document 32. Offline event ordering is monotonic by sequence, not maximum position.

Download preparation has independent artifact ownership and retention even if it calls shared remux/transcode workers. Playback leases cannot be reused as perpetual download authorization. A prepared artifact is finite, stable, length/digest verified and source/version/quality-bound before ready. Reuse across requests requires exact transformation/byte identity; each viewer still receives separate authorization. Cancelled output cannot publish later through a new attempt without new explicit intent.

The receipt stores issuance authorization revision and stable owner. Revalidation authenticates the same stable owner under current policy; differing current revision alone is neither invalid nor out-of-scope. It issues a new immutable receipt if still authorized, otherwise returns the exact privacy-safe outcome. Expiry/unreachability preserves bytes but blocks use after thirty days. Learned revocation/sign-out/intrinsic integrity failure follows the original resumable deletion rules. Inactive-profile bytes remain hidden and protected, not corrupt.

Trusted last server verification time and platform monotonic elapsed time where available prevent trivial clock rollback from extending a receipt. Across reboot or uncertain clock rollback, require revalidation instead of granting extra days; do not invent offline DRM or claim protection against a device owner modifying the application. Digest verification occurs on acquisition/resume and after detected storage change; do not require a full huge-file hash before every playback start when protected verified-file identity remains coherent. Platform data protection and bounded background verification preserve both integrity and usable startup.

OS background transfers use an installation-owned durable registry linking task IDs to exact artifact, stable owner and operation generation. On launch, reconcile OS tasks, private partial files and catalog state. Late completion after sign-out/cancel cannot publish. A renewed transfer grant may resume only the same artifact after current authorization, range and length validation. Low-space/changed removable storage stops transfer safely and leaves unrelated downloads intact. Never report reclaimed bytes until deletion is observed.

## Live TV and DVR

A stable programme occurrence is distinct from its guide revision/airing-time observation. Provider corrections update future scheduled intent only when identity continuity is proven. Reimporting the same programme at a corrected time does not create another recording. Unknown/removed mappings remain issues for owner review; do not silently retarget by title. Build atomic active guide generations with bounded staging and UTC instants; retain timezone for rule interpretation/display. Test repeated/skipped DST times and rules crossing midnight.

Retain explicit recording priorities, earlier-start/stable-ID tie-breaks and the visible reservation countdown. These are owner/product tuner commitments, not predictive CPU-load eviction. Unknown tuner count is shown as unknown with a conservative planning estimate of one until discovery/owner configuration; that estimate alone does not become an ordinary playback-stream cap. Serialize uncertain tune attempts through the adapter, observe actual refusal/exclusive resource use, and preserve active streams. A confirmed finite device or explicit owner tuner cap is enforceable. Future guide conflicts may be forecast as at-risk rather than fabricated certainty.

Tuner allocation and playback occurrence are separate leases joined by identity. Changing channel transfers/releases only the named allocation. If preparation cannot safely overlap, use stop-then-tune with truthful transition. DVR allocation renewal comes from the actual capture worker; buffered client playback cannot prolong a dead recording writer. Cancellation fences output publication and releases only the matching lease generation.

Use lease-specific partial paths and a publication journal. Completion needs observed usable capture over the intended interval with explicit gap/truncation accounting, not only exit zero, file size or provider EOF. A valid partial remains incomplete and playable. After crash, verify published versus partial output and retained capture intervals before choosing completed/incomplete/failed. Do not restart an expired programme as if it could recover missed live bytes.

Retention considers Keep, configured rule limits, ownership, capture/playback/download/backup leases and durable pending-delete state. First fence new use at the deletion commit, then wait/drain existing protected readers, then delete exact owned artifacts. A guide disappearing, profile rename, policy revision or absent media root is not deletion authority. Source disable stops new admission; removal with dependent recordings requires explicit resolution. Recorded TV remains an authorized catalog projection, not a public file endpoint.

## Sharing, receivers and Watch Together

Invitation acceptance remains Hosted-owned, succeeds while the server is offline, and never proves local access before signed policy is applied. Preserve the accepted concurrent distinct-recipient invitation guard advancement in journey 08. Ordinary stale/revoked/expired invites cannot inherit that exception. Resend rotates delivery proof within the same invitation and does not reset accepted membership.

Receiver registration/control is distinct from a viewer login and from media-grant authority. Preserve direct-LAN first-party command behavior and the server authorization boundary. The original X25519/HKDF/AES-GCM description is not permission to invent an ad hoc cryptographic protocol: the adapter must use a reviewed standardized construction with fixed domain separation, authenticated sender/receiver key binding, nonce/replay rules and test vectors. A library primitive name or successful encrypt/decrypt test alone does not qualify the transport. One shared wire definition must precede per-platform implementations. Unsupported secure transport hides that destination capability, never falls back to plaintext bearer commands.

All first-playing handoff prescriptions in the original corpus are replaced by document 32's readiness-based atomic commit with paused/unpresented candidates. Controller disconnection leaves committed receiver playback alive; Stop revokes it. An ambiguous timeout cannot authorize both actors or resume a source whose ownership already moved. A detached old-server controller has only the explicitly retained operation rights, not a second unrestricted browsing identity.

Watch Together retains host-only commands, explicit invitations, Start anyway, no automatic group pause for one buffering participant, 0.75/3-second correction bands, and host-loss pause/end at two/ten minutes. Each participant/device has an independent playback occurrence; same-profile joining does not imply takeover. Personal state arbitration follows document 32, not room order or last network arrival. A host transfer compares group/host revision and cannot create two hosts. After restart, reconstruct the group snapshot and elapsed deadline from durable evidence or end explicitly; do not restart elapsed host timers or replay disconnected commands.

Separate group membership, group timeline, each participant's desired/observed player state and transport reconnect generation. Estimate server-relative time using bounded round-trip evidence and monotonic elapsed clocks; raw client wall clocks do not command the group. A slow member catches up within its capabilities without feeding corrective seek loops into host commands. Authorization gates every snapshot, queue entry and load. A future inaccessible item remains an opaque placeholder; host resolution is required before it becomes current.

## Settings, restore and distribution

Preferences have a declared owner and runtime consumer. Profile-server viewing preferences stay on the selected server even for Hosted accounts; Hosted global profile identity/PIN/security remains global. Registry fields expose requested/effective values and application mode. Hot in-process changes can commit/apply atomically; external changes require candidate validation and a durable desired/effective operation, not a fictional DB/filesystem transaction.

The viewer preference registry is published on `GET /v1/preferences` as `registry {revision, fields[]}`, each field carrying `key` (dotted namespace), `type`, `default`, `allowedValues` or `min`/`max`, `scopes[]`, `group` and `labelKey`; clients generate their settings surfaces from it and never carry their own defaults, domains or limits. Viewer fields declare exactly one of `profile-server` or `profile-device-class`; no viewer field declares a session override, so `/v1/preferences` accepts those two scopes only, and the viewer entries are removed from the owner console registry so a client has one authority per field rather than two. `PATCH /v1/preferences` is a merge over one scope document: submitted keys are written, an explicit `null` removes that scope's override, omitted keys are untouched, and an unknown key or a key outside the addressed scope is rejected by name. A value outside a declared numeric range is stored clamped to that range and reported in `clampedFields[]`; an enumerated value outside its domain, or a value of the wrong type, is rejected rather than corrected. A server policy limit — a cellular ladder on a device class without cellular — changes only the effective value, leaving the saved choice intact, and shows as `effectiveSource` `policy`. `playback.startedThresholdPercent` and `playback.playedThresholdPercent` are the authority for personal progress and history classification, with the existing thirty-second started ceiling kept as a maximum. `privacy.pauseWatchHistory` stops new personal progress and history writes for that viewer; existing progress still resumes and watched/watchlist mutations still apply. `search.rememberHistory` gates both recording and `GET /v1/search/history`, which with the preference off returns an empty list without deleting what is already stored.

Support's current bounded JSON export is a valid completed slice, not full logs/diagnostics/backup completion. Broader support selection/redaction remains future scope. Sensitive audit writes commit atomically or via durable outbox; a failed audit cannot accompany a successful sensitive mutation. Routine diagnostic failures must not break ordinary playback. File-local hash chaining cannot promise tamper-proof logs against an operator with full host access; claims are limited to integrity/tamper evidence under the stated storage trust boundary.

Backup uses a database-consistent snapshot plus a component manifest linking secret references, identity keys, selected artwork and required configuration generations. Ordinary backups exclude original media and active credentials. Required encrypted secret components must have an available independently recoverable key; otherwise restoreReady is false with exact missing prerequisites. The Local recovery-owner credential remains excluded unless the owner explicitly supplies the required protected backup key. An unencrypted database snapshot containing configuration secrets is not an acceptable general backup implementation.

Restore has a supervisor journal outside the replaced database, a verified safety copy and a fresh unpredictable security incarnation (or external monotonic epoch plus incarnation) durable before serving again. Both success and rollback fence restored credentials/receipts. Do not load an old epoch from backup and increment it, which may recreate a value already used. The recovery/status capability belongs to the supervisor and exact operation, not the invalidated restored session tables. Losing that capability does not start a second restore; Local recovery administration can discover the in-progress operation safely.

Retain server identity only through an explicit same-server restore. A cloned installation must not advertise the same identity concurrently; require an explicit new-identity workflow. Current Hosted policy must reconcile before Hosted access returns after restore; Local recovery remains the outage path. An offline client that has not learned of restore may still hold a valid thirty-day receipt under the accepted offline model. Restore is not magic instantaneous remote wipe. When it reconnects, old-incarnation receipt revalidation fails according to explicit revocation policy.

Default server port remains 32500, with deliberate development overrides. Installations run as OS-managed services with explicit data/config/cache separation and least necessary privileges. Installer upgrade/removal distinguishes binaries, service registration, application state, backups and original media; no default media deletion. Manual signed updates remain default. Verify authenticity, compatibility, staging, health and rollback data prerequisites; never imply that installing an older binary downgrades its database. Hosted self-managed backup/recovery is separately tested; this does not require a managed or distributed database before launch.

## Presentation and scope preservation

Retain the reviewed new Manrope/blue atmospheric appearance, canonical marks, named-library rail, top-right web account menu, correct hierarchies and original detailed product interactions. Original token values are visual reference, not instructions to undo accepted new palette/geometry. Native focus engines own ordinary TV movement; one-shot restoration does not introduce a competing JS spatial engine. Cards, large text, keyboard/VoiceOver, stable shell and backdrop contrast still require actual visual/interactive qualification.

Search text may exist in a scoped, in-memory search service while navigating away and back during a visit. It does not enter ordinary route URLs, browser-history payloads, persistent restoration, focus IDs or logs. An explicit exported/shared search link is not introduced by this reconciliation. Server sort/filter semantics remain authoritative; client query drafts do not implement filtering locally.

Broad server administration remains web-first. Native personal settings, account/profile flows, playback, guide, recording actions and eligible status are still required; provider secrets, roots, restore, logs and update administration use a secure web handoff. Original generic references to native management do not require duplicating the entire Server Console.

Consumer notifications are a selected-server inbox. Hosted may deliver only the already-contracted optional opaque account/invitation wake, not ordinary background media/activity notifications. No room state or media description accompanies that wake. Device push registration is not permission to invent a global notification service.
