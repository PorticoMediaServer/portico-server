## What to deliver
1. **The planner chooses the best output the device can take**, in this order of preference: play the file as it is; remux; convert audio only (keeping the video untouched); convert video keeping as much as the device supports — HEVC for a device that decodes HEVC when the quality asked for allows it, HDR preserved for a device and display that take it, tone mapped otherwise, 10-bit kept when supported; lossless or multichannel audio kept (copy, then FLAC or E-AC-3/AC-3, before any lossy stereo) according to the device's declared codecs, channels and passthrough. Never a silent downgrade to 384 kbps AAC when something better is accepted.
2. **Every output the conversion code can produce is registered with the planner** and reachable; every planner decision maps to a target the pipeline honours. Add a table-driven test of device profiles (Apple TV 4K native and mpv, an older Apple TV HD, iPhone, Android phone with and without HEVC hardware, Fire TV Stick, a Chromecast-class device, desktop Chrome, Safari, Firefox, a Vega device) against source files (H.264 SDR stereo; HEVC 10-bit HDR10 with TrueHD 7.1; Dolby Vision profiles 5, 7 and 8; AV1; MPEG-2 interlaced with AC-3; VC-1 with DTS-HD; HLG) asserting the plan each gets.
3. **Subtitles in the plan**: a device that draws a styled or image track itself gets the original beside the stream; one that cannot gets burn-in through the new high-quality path; the Automatic engine rule prefers mpv over burn-in where an mpv profile can draw it.
4. **Fragmented MP4 conversions end to end**: run the software path against the real producer on tiny generated samples (H.264 and, if the bundled FFmpeg has a software HEVC encoder, HEVC) and fix what breaks in playlists, init segments, seeks and re-plans.
5. **Quality ladder per codec**: the fixed qualities map to sensible bitrates for H.264 and HEVC at each resolution; "Original" with a codec change uses a quality target instead of a fixed bitrate.
6. **Live TV and downloads read the same decisions**: live copy-or-convert and the offered download qualities come from the same capability document and target list, with no second classification.
7. Hardware paths cannot be run here: argument-level tests per vendor and exact GPU test notes.
