## What to deliver
1. **Styled subtitles (ASS/SSA) rendered in the browser** with a WebAssembly build of libass, including the fonts embedded in the file and a sensible fallback font set for scripts the default font lacks. Vendor the WebAssembly build and its worker into the repository the way existing third-party code is vendored (see `third_party/` and `THIRD-PARTY-NOTICES.md` for the house style: source, version, licence, how it was obtained, digest). Render on a canvas over the video, in a worker, in step with playback (seeking, speed changes, pause), sized correctly on resize, fullscreen and high-density screens, and released when the track or title changes. Load the engine only when a styled track is actually selected.
2. **Image subtitles rendered in the browser, written by us**: PGS (`.sup` presentation, window, palette and object segments, including run-length decoding, cropping, forced flags and palette updates), VobSub (`idx` + `sub`) and, if reasonable, DVB. Decode in a worker, draw on the same overlay canvas, scaled from the subtitle's own video size, in step with playback. Bounded against hostile files. Table-driven tests with small generated samples.
3. **The server side of this is another lane's**: the subtitles-text lane is adding, right now, routes that deliver the styled original with its attached fonts and the image originals, and a per-track list of delivery options; its work is in `/home/justin/projects/Portico/.worktrees/audit-implementation/server-subtitles-text` (read-only for you) and its report is `/home/justin/projects/Portico/.worktrees/audit-implementation/_program/reports/subtitles-text.md` (it may still be growing; read it when you reach the wiring step and again before you finish). Build your renderers behind one small interface that takes bytes or a URL, wire them to those routes through the `client-core` subtitle services, and if the routes are not final when you finish, say exactly what is left to connect.
4. **The web capability declaration**: the web player must tell the server what it renders itself, using `subtitleRendering` values `text`, `ass`, `pgs`, `vobsub`, `dvb`, so the server stops burning those in. The playback-core lane is replacing the capability document at this moment (`/home/justin/projects/Portico/.worktrees/audit-implementation/server-playback-core`, report `/home/justin/projects/Portico/.worktrees/audit-implementation/_program/reports/playback-core.md` when it exists); put the declaration in one place so it can be re-pointed, and note it.
5. **Viewer caption style**: Portico's caption style settings apply to text subtitles; styled (ASS) tracks keep their authored look except for an overall size and position adjustment.
6. **The web player's leftovers** from its report: deep resume for MP3, ADTS and Ogg without reading everything before the position; audiobook speed above 2×; "Up next" during credits; native HLS on Safari where it is the right path. Do the ones that are sound; explain any you leave.
