## 2. Exact resume in MP3/ADTS/Ogg without converting the file (Justin: the FLAC conversion "seems overkill… there's a better way that doesn't involve processing the file")
- He is right. Replace the deep-start FLAC conversion (`AudioPlan.DeepStart`, the converted route's deep start, client `deepStart`) with a **seek index**: the server records, once per file (during analysis/scan, or lazily on first need and then cached as derived data — choose the cheaper overall; per-item cost must stay flat), a compact table of byte offset ↔ sample position (e.g. a frame boundary every few seconds; for Ogg, page granule positions; for ADTS, frame boundaries; for MP3, frame boundaries accounting for the LAME/Xing header and encoder delay). The plan carries the index (or a route serves it); the client's own decoder reads the file directly with a Range request from the nearest indexed offset at or before the target, decodes, and discards samples up to the exact position. Gapless trims, crossfade and gains keep working. No transcoding, no FFmpeg process at play time.
- Keep it bounded (index size proportional to duration with a cap; e.g. one entry per ~2–5 s), stored in the baseline schema as derived data with the existing generation/invalidation rules for file changes.
- Also make the **browser's own** `<audio>` path (non-gapless) use plain Range seeking as today.
- Tests: server index builder per format with real FFmpeg-generated fixtures (VBR MP3 with Xing, CBR MP3 without, ADTS AAC, Ogg Vorbis and Opus), exact-sample landing in the client decoder test, and that no conversion route is used. Remove the FLAC deep-start tests/code.
