## What to deliver
1. **Wire it all together end to end**: a scanned file's folder-and-file evidence flows into matching and into the title attach point; a second copy becomes a version; editions and parts are read from names and reach the version and title; extras attach to their title instead of becoming titles; ignore rules apply (including `.plexignore` / `.ignore` files found during the walk); the file wins where folder and file disagree. Remove the temporary adapters the earlier lanes left.
2. **Scans that tolerate a real disk** (D-02): a folder that changes during a scan must not fail the scan and block analysis (B-05.2): take what was seen, pick up the change next pass. One unreadable sub-folder must not stop every scan of that source (B-05.4): skip it, report it, carry on. A file that cannot be probed is catalogued by name and reported, not dropped. Everything skipped is listed for the owner with a plain reason.
3. **Pace** (D-21): the scan runs as fast as the storage allows within the shared three-level background speed (gentle, normal, fast; the providers lane added the setting `backgroundSpeed`), yielding to playback. A first import of a few thousand films should take minutes to list and tens of minutes to match, not days. Analysis must not stop entirely while something plays from the same source (A-05.34): it slows down.
4. **Bookkeeping that does not grow forever**: scan bookkeeping is never pruned (B-05.20) and every scan re-queues every file (B-05.21). Prune, and queue only what changed.
5. **Knowing about changes without a full scan** (D-50): watch local library folders for changes (inotify, FSEvents, ReadDirectoryChangesW behind one interface, with a sensible fallback for network mounts and a bounded number of watches), debounce, and scan only the affected folders through the same limited-scan path the "paths changed" call uses. An owner setting per library turns it off. A removal reported by the paths-changed call or the watcher is acted on at once when the folder itself is readable.
6. **Re-observe sidecars**: a changed, added or deleted NFO, artwork or subtitle file beside an unchanged media file is noticed.
7. Every other confirmed scan bug in document 05 that is still present.
