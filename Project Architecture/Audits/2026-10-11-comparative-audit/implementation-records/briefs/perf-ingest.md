**Your area**: everything that happens when items enter or leave a library: the scan walk and inventory, name reading and matching, attaching files to titles (versions, editions, extras), probing and analysis scheduling, metadata writes, the catalogue writes and every trigger they fire, the events and counters each write publishes, missing-file handling, library removal, and the personal-state writes of ordinary use (progress ticks, marking watched, undo, history). The key questions: **is the time to add one item constant as the library grows? If it rises, how fast, and why?** The same for a progress tick and marking a 500-episode show watched. Look for work that grows with the library inside a per-item write (a count or scan over a whole table, a trigger that touches every row of a parent, a full re-derivation of a large group because one member changed), write amplification (bytes and rows written per item added; the capacity reports measured some), per-item round trips that could be batched within a scan, repeated reads of what was just written, and long write-gate holds in large actions (library removal, mark-watched on a big show, merges). Measure the add-item rate at several library sizes with the benchmark tool or a focused benchmark, fix what grows, and re-measure.
