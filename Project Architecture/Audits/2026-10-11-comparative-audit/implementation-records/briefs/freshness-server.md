## What to deliver
1. **Browse and search always answer** (Justin: the server can NEVER say "being prepared"). Today raising a derivation version makes browse or search unavailable for the whole rebuild (B-07.2). Rebuild into a new generation beside the old one and switch when it is ready; until then serve the previous generation. On a first-ever build serve what has been built so far. Library changes arrive in small chunks with frequent checkpoints, so what is served is at most slightly behind. Remove every "being prepared" answer from browse and search paths and from the client contract.
2. **One bad title cannot stall the workers** (B-07.1): set it aside with a reason the owner can see, carry on, retry it later. A rebuild that contains such a title still finishes.
3. **Split the catch-all revision counters** (D-08): a playback progress tick must not invalidate browse cursors or Home (B-07.4, B-12.20); a token renewal must not look like a change to everything (B-19.2). Separate counters for content order, personal state, commands and observations, per resource where needed, so a cursor or cached document is invalidated only by a change that affects it. A stale cursor never produces an error a person sees: it re-reads from the nearest valid position.
4. **Publish changes** on the event feed: watch state and progress changes (to that profile's devices), library changes (titles added, updated, removed, missing, restored), scan progress, and settings changes clients care about. Events are small, carry the counters above, and are batched so a large scan does not flood: a screen should learn of a change within about 30 seconds at most, usually within a few. Replace the two long-poll listeners with one efficient stream (server-sent events, with long-poll kept only if a platform needs it); an idle server with idle clients does no database work.
5. **Clear derived per-library tables** when a library is removed.
6. **Growth without bound** (B-07.15): prune ledgers, vocabularies and event history on a schedule.
7. Every other confirmed bug in document 07 and the event entries of document 08 that is still present.
