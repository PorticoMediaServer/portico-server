### B-22.26 — Activation polling bypasses the shared outage gate
- Status: SKIPPED
- What I found: Real as described. `src/bridge/setup-codes.ts:21-31` calls an ungated `HttpLocalApi`; the fixed 5 s retry is in `packages/client-core/src/setup-code.ts:179-185`.
- Reason: (1) the cadence defect is in `packages/`, which this lane must not edit; (2) wrapping the bridge calls in `hostedGate(...)` conflicts with Networking contract §10 (visible activation retries start ~5 s, exponential with jitter, cap 30 s; the gate backs off to ~21 minutes) and an open gate would block a person's first code; (3) reporting outcomes without being gated would push the shared gate to its maximum within ~40 s.
- Precise fix for later: in canonical `setup-code.ts`, give poll transport failures the 5→30 s exponential backoff with jitter that create has, add jitter to create, let `SetupCodeApi` distinguish person-initiated from automatic create, then decide whether activation reports to or obeys `hostedGate` and with what cap. Keep the envelope and key checks in `poll` outside any gate wrapper.

### B-19.1 — Cold-launch link thrown away
- Status: SKIPPED (not as described; a narrower defect remains)
- What I found: the launch URL does reach JavaScript on all platforms via `getInitialURL()`. `src/shell/Shell.tsx:259` drops it at the Shell's first mount because the API is still the placeholder, but the Shell is unmounted and remounted when the viewer commit publishes (`src/app/session.tsx:372, 418`, `App.tsx:22`), and re-reads `getInitialURL()` with the real API (`Shell.tsx:294`). So the audit's "nothing replays the URL later" is wrong by reading.
- Real gaps: (1) iOS Handoff, Spotlight, Siri and universal links arrive as a `url` event 2 s after launch (`PorticoIntents.swift:13-19`) and are lost if restore has not finished; (2) the launch link is re-handled on every later Shell mount in the same process (profile switch, server switch, sign-in again), contradicting NAV-11 "consume the intent exactly once" and its ten-minute expiry.
- Precise fix for later: a module-level pending-link owner per NAV-11 (read `getInitialURL()` once per process; subscribe to `url` above the Shell; hold at most one link with timestamp and viewer key; replay once when the origin is real and the viewer key matches; discard on mismatch or after ten minutes). Same owner B-21.14 needs. This is a design change, not a correction of the listed defect.
