## Summary

Independent review answered all 73 entries: 31 Q questions, 12 competitor risks and 30 lesson standings. Across the questions/risks: **2 handled, 19 exposed, 19 partly, 3 unsettled**. Across lessons: **1 handled, 8 exposed, 17 partly, 4 unsettled**. “Exposed” includes explicitly labelled design risks/trade-offs; it does not always mean a reproduced defect. Sizes on handled/unsettled entries cover acceptance or optional work, not speculative mandatory fixes. All questions were treated with Tier 1 rigor; no Tier 2 list was assigned.

The useful safeguards held up: automatic missing-source reconciliation preserves logical history, NFO parsing is bounded, source/generation fences exist, and the VOD hardware fallback keeps requested quality. Important confirmed failures sit at observation, translation and lifecycle boundaries: missed in-place overwrites, dropped player/capability choices, native HTTP subtitle refusal, group revision/liveness, Cast sender departure, download resume/conflicts, guide-triggered retunes and audiobook continuation. Existing B findings are cited only after an independent source look; two additional mechanisms are recorded under New findings.

Several first-pass uncertainties should be narrowed. Support/intake policy exists, artist enrichment is already windowed, and local cast/provider crew coexistence is repaired. Analysis preemption is a recorded exception in the specific scan contract, conflicting with the overview's absolute scheduling wording. Physical A/V timing, HDR fidelity, timeshift mapping, CPU qualification and store delivery remain unproved. The High consequences originally attached to those questions are not treated as confirmed High bugs.

### Q-24.3 Does an in-place media overwrite remain invisible to incremental scans?
- **First pass:** Probable source-derived bug; no runtime reproduction; severity Medium (the source rates conditional consequences, not reproduction).
- **What I traced:** queue automatically picks incremental within seven days of an integrity/full run (`server/internal/ingestion/incremental.go:24`). Before directory enumeration, skip compares identity plus `InventoryRevision` (`:59`, `:69`); equality only schedules cached child directories (`:84`, `:108`). `server/internal/storage/inventory_page.go:46` hashes the directory snapshot's identity/change token/size/mtime, and `:272` stats the directory. There is no restat of its direct files on the skip branch. `scanevents` is scan event publication, not a filesystem watcher repairing this branch.
- **Answer:** **Portico is exposed — Confirmed.** An ordinary same-inode overwrite can preserve directory stat data while changing file size/mtime; incremental scan retains old facts until a full/integrity walk. Weekly integrity is chosen when a scan is queued, not an unconditional seven-day repair daemon. **Class:** Defect. **Severity:** Medium; overwritten library files have stale facts/artifacts and may fail freshness checks. **Size:** **M**.
- **Fix direction:** change `ingestion/incremental.go` and storage inventory to validate known file revisions in bounded pages, or use trustworthy change evidence plus a fallback. Keep logical personal identity and invalidate dependent revisions together.
- **Related / Backlog:** agree with B-05.3, L-24.11 and R-23.6; exact Backlog item exists. **Experiment performed:** Python standard-library temporary directory under `/tmp`, write one byte, stat parent/file, overwrite same file with four bytes, restat. Parent dev/inode/size/mtime were unchanged; file size/mtime changed. No Portico function or state executed; this proves the filesystem premise on this host, not the running product.
